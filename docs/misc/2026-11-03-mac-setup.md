# Running BadCode's Suno automation on a Mac

Written 2026-11-03 for Tom (music), so he gets the same Claude Code + Suno experience Jack has,
on macOS, with no Linux VM. Premiere and Flow are out of scope here.

## Why it works without a VM

The Suno automation never needed Linux. It is a Node script (`scripts/suno/suno.mts`) that opens
an ordinary Google Chrome with a remote-control port (CDP) and its own profile folder
(`.flow-profile/`), then drives suno.com/create through that port. The launcher
(`scripts/flow-chrome.sh`) already looks for Chrome at `/Applications/Google Chrome.app`.
On a Mac, Chrome and the script are on the same machine, which is simpler than WSL, not harder.

| Works on a Mac | Does not |
| --- | --- |
| `status`, `extract`, `load`, `controls`, `pair`, `grid-plan`, `grid`, `takes` | `record` (captures audio through PulseAudio, Linux only — it now says so and stops) |
| All the skills: `suno-prompt`, `suno-automation`, `variations`, `story-style`, `story-craft` | `premiere-automation` (WSL-to-Windows bridge) |
| The same-prompt check hook (needs `python3`) | The `listen` tool (built on the same recorder) |

Recording only matters for Claude listening to a take, which is done only when asked anyway.
On the Mac: listen in the browser, and download by hand (downloads are always human — Suno caps them).

## Setup (about 20 minutes, once)

1. **GitHub access**: Tom needs read/write on the private repo `badcodetv/core` and an SSH key
   (or `gh auth login`).
2. **Xcode tools** (git, python3): `xcode-select --install`
3. **Node 22+**: `brew install node@22`, or the installer from nodejs.org.
4. **Google Chrome** in `/Applications`.
5. **Claude Code**: `npm install -g @anthropic-ai/claude-code`, then `claude` and sign in with
   Tom's own Claude account.
6. **Clone and check**:
   ```bash
   git clone git@github.com:badcodetv/core.git badcode && cd badcode
   ./scripts/mac-check.sh
   ```
   This checks the tools, runs `npm install`, opens a new Chrome window and reads Suno's form back.
7. **Sign in to Suno** in that Chrome window (not Tom's everyday Chrome — it is a separate profile).
   Leave it open. Run `./scripts/mac-check.sh` again: it should now show the create form.
8. **Start Claude** in the repo folder: `claude`. Approve the project's MCP servers if asked
   (only `playwright` matters for Suno; `flow`, `premiere` and `listen` can be declined).

## First prompt to give Claude on the Mac

> I'm Tom, working on BadCode's music, on a Mac. Read docs/misc/2026-11-03-mac-setup.md.
> `record` and Premiere don't work on this machine. Run `npx tsx scripts/suno/suno.mts status`.

## Rules that still apply

- **One Suno session per Suno account at a time.** Suno has one create form per account; a second
  session loading the form wipes the first one's. If Tom uses the BadCode Suno account, he and Jack
  must not drive it at the same time. His own Suno account avoids this.
- **Never automate downloads.**
- **Media paths**: generated files live outside the repo. If Tom makes media worth keeping, set
  `export BADCODE_MEDIA_ROOT=~/badcode-media` in his shell profile (the default is Kai's `D:` drive).

## If something breaks

- `NO_CONTEXT` / nothing opens: `./scripts/browser-channel.sh list`, then `./scripts/browser-channel.sh up 1`.
- Chrome log: `/tmp/flow-chrome-9222.log`.
- macOS may ask to allow Chrome or Terminal network access the first time: allow it.
- Chrome shows a yellow "--no-sandbox" warning bar: harmless, close it.

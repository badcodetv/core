Kai wants to consolidate "working in Claude Code" with "developing the comic." Decomposed into 3 sub-projects, each its own spec→plan→build:

- **SP1 — Library ergonomics + authoring doc** ✅ shipped Jun 2026 (branch feat/comic-asset-pipeline). `ScrollComic pageDefaults` + `Page hold` shorthand + library defaults (crossfade/hold 1) resolved by pure `resolvePage` (packages/comic/src/components/pageDefaults.ts); colocated `comics/<name>/effects.ts` convention (graduate to `@badcode/comic/effects` on 2nd consumer); `packages/comic/AUTHORING.md` is the guide for Claude; generator (packages/cli/src/generate.ts) emits the lean API; camping + karen migrated. Spec: docs/superpowers/specs/2026-06-18-comic-library-ergonomics-design.md. Plan: docs/superpowers/plans/2026-06-18-comic-library-ergonomics.md.
- **SP2 — Comic-authoring skill** ⏳ pending. A Claude Code skill that knows the library + canon, adds/edits/reorders pages and attaches effects, and keeps `docs/<story>/` canon in sync with the comic .tsx (they currently drift — story lives inline in the TSX). Will lean on AUTHORING.md.
- **SP3 — Image-generation loop** 🚧 spec + Phase-1 plan written 2026-06-20, not yet executed. Reframed as a **Flow automation loop**: drive logged-in Google Flow via Playwright-attached-over-CDP to generate slide images and push them to the bucket. Decided spike-first (Claude-in-the-loop via `@playwright/mcp` over `--cdp-endpoint`) then harden into a deterministic `badcode flow` CLI command; Claude judges best-of-N candidates, human spot-checks a final contact sheet; reference attachment not hard-fixed to disk (setInputFiles from bucket temp / Drive picker / in-project gallery). Spec: docs/superpowers/specs/2026-06-20-flow-automation-loop-design.md. Phase-1 plan: docs/superpowers/plans/2026-06-20-flow-automation-spike.md (4 tasks: logged-in Chrome+CDP launcher, attach Playwright MCP, TDD'd `badcode flow-prep` helper, interactive spike of one Camping slide + a recorded `docs/superpowers/flow-selectors.md` map). The other two pipeline gaps — A (idea→design/greenlight workflow with a media checklist) and B (idea→comic storyboard = populating `comic.meta.ts` scenes; SP2 territory) — deferred to their own cycles. Builds on CLI `prompt`/`push` + the `Bucket` interface.

**UPDATE 2026-06-25 — the `make-comic` skill shipped (merged to main, PR #3).** SP3's Flow loop was proven end-to-end and SP2's "skill that authors comics from canon" is largely delivered by `make-comic`, a gated six-stage workflow (idea → characters → character images → storyboard → storyboard images → assemble) that composes new-story + Google Flow + @badcode/comic. See [[flow-automation-integration]]. Spec: docs/superpowers/specs/2026-06-25-make-comic-skill-design.md; plan: docs/superpowers/plans/2026-06-25-make-comic-skill.md. First comic produced through it: "The Magic Money Tree" (docs/magic-money-tree/, live at /comics/magic-money-tree). NOT yet covered: SP2's keep-canon-in-sync-with-an-EXISTING-hand-written-.tsx case (make-comic generates fresh, doesn't reconcile drift in camping/karen); the `badcode flow` deterministic CLI hardening (make-comic drives Flow via the MCP recipe instead); migrating make-comic's derived images from public/ to the assets-build bucket pipeline.

Process used: brainstorming → writing-plans → executed via a background Workflow of 6 sequential Sonnet agents (one per task, gated on tests/typecheck/build). See [[progressive-comic-loading]]. (make-comic itself: brainstorming → writing-plans → executing-plans inline → finishing-a-development-branch.)
